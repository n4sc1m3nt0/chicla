# docs/

Reference material that came with the project. Nothing here is wired into the build.

| File | What it is |
| --- | --- |
| `zipkit-plan-ronda-1s.md` | The original zipkit plan (round 1s), verbatim. Superseded by `ROADMAP.md`; kept for the reasoning behind the `chicla-zip` guarantees (§3), the test list (§4, step 1a to 1c) and the NFC/NFD collision decision (§7). |
| `zipkit-RASCUNHO.mjs` | The zipkit draft, verbatim. Passes `node --check`; has no tests. Known bugs are listed in `ROADMAP.md` §13 (B1 to B7). It is the untouched original: C1.1 took it into `packages/chicla-zip/src/zipkit.mjs` with one change (`Readable.from([])` instead of `Transform.from([])`, see B7), so do not edit this copy. |
| `zip-handling.md` | How `chicla-zip` handles zips: why (bit 11, locales, `unzip -UU` vs `ditto`), what the reader, extractor and writers promise, options with a catch, `collisions`, known limits and what was not checked. Written in round 35 (C4.3). |
| `manifest.md` | `FILES.manifest` formats v1 and v2: fields, who writes and reads it, what `check-manifest` and `verify-delivery-zip` check (crc32 and size against the zip's central directory), the exempt baseline, the `EMANIFEST_*` codes and the limits. Written in round 72 (C7.1 slice c). |
| `pinned-files-design.md` | Design note (round 127, C11.1 slice 5g): how the four pinned recovery files (`baseline`, `manifest`, `policy`, `recovery-report`) can move into the kit package without moving the digest of `RECOVER/`, the options, the slices and the new gate G-C11. A plan, not wired in. Since round 272 (C21.2) §8, **What an edit of a pinned file costs**: the five steps, and where the digest lives. |
| `release.md` | The runbook of the single package `chicla`: the CI tarball, the checks, tag, GitHub release, `npm publish` by the owner, what npm serves, then `npm deprecate` of the old names. It also keeps the sections of `chicla-zip` and `chicla-kit` 0.1.x as history. |
| `fingerprint.md` | The fingerprint specified: the triple (`seq`, app hash, changelog hash), the three legs and exactly which bytes each hash covers, the shape of the two comment lines, the checks `--verify` prints in order, bump / refresh / dry-run, the toolchain pin and the `EBUMP_*` codes. Written in round 180 (C10.4); `test/fingerprint-docs.test.mjs` fails when it drifts from the code. |
| `state-file.md` | The status file specified: name and number, the seven required parts and who writes each, the order from the fingerprint on, what the next session reads first, and what `bump-round` refuses (`EBUMP_STATUS`; bump and refresh only, not `--verify`). Written in round 181 (C10.5); `test/state-file-docs.test.mjs` fails when it drifts from the code. |

| `status-archive-previous-<lo>-<hi>.md` | The old `**Previous (round N):**` blocks of the status file, moved here verbatim by `node scripts/archive-changelog.mjs --status` (round 238, C16.4). History; nothing was edited or deleted. |
| `status-archive-done-<lo>-<hi>.md` | The older lines of the status file's `## Snapshot`, moved here verbatim by `node scripts/archive-changelog.mjs --snapshot` (round 241, C16.7, D139). History; nothing was edited or deleted. |
| `audits/AUDIT-1.md` to `AUDIT-3.md` | The gap audits of the first milestones (promised vs. what exists, real bugs, missing behaviour). |
| `audits/AUDIT-4.md` | The whole-project audit of 2026-10-22 (round 233b): security, performance and token efficiency, with measurements, and the plan of six rounds (C16.1 to C16.6). |
| `../packages/chicla-kit/mutants/list.mjs` | The kit's hand mutants (`K-INT-`, `K-DMP-`, `K-REC-`, `K-MAN-`, `K-DEL-`, `K-PNL-`, `K-ARC-`, `K-BMP-`, `K-CMN-`, `K-VER-`): each breaks one guarantee on purpose and its test must go red. Run with `npm run mutants:kit` (`--pkg .`: the whole tree is copied, because the kit tests read the project root; `-- --only <id> --timeout 60` for one). Not part of `npm run mutants`, which runs the zip list (348). The whole kit pass takes about half an hour on 2 cores (AUDIT-7 §6). |
| `audits/AUDIT-5.md` | The audit after M16 and M17 (round 248, 2026-10-26): promised against what exists, five measured findings (archives overdue, two paragraphs that grow by hand, kit mutants not repeatable, uneven coverage, a stale timing), what was not measured, and the plan M18 (C18.1 to C18.4). |
| `audits/AUDIT-6.md` | The audit after M18 (round 256, 2026-10-27): promised against what exists, six measured findings (archive limits hit by hand, an unknown option that archives for real, tests that read text the archives move, the kit mutant list undocumented and partial, a paragraph past 4 KB), the plan of five cards (C19.1 to C19.5) and the result of one whole `npm run mutants:kit` pass. |
| `audits/AUDIT-7.md` | The audit after M19 (round 265, 2026-10-27): promised against what exists, six measured findings (`scripts/bump-round.mjs` bumps for real on an option it does not know, stale figures about the kit mutant list, a test that reads a count from the live files, stale ROADMAP states, the zip list not run whole since 2026-10-17, coverage of the files M19 touched), the plan of five cards (C20.1 to C20.5) and the result of one whole `npm run mutants:kit` pass (126 entries, about 34 minutes). |
| `audits/AUDIT-8.md` | The audit after M23 (round 283, 2026-10-29): the published `chicla` 0.2.0 read from the registry and driven as a user would; the record is true (byte-identical tarball, deprecations), seven findings (`chicla recovery` does not start in the package, `init` makes a project that `make-delivery` refuses, `dump` from the package carries no `RECOVER/`, the CI never runs the tarball, stale words about the old packages, the loader has no mutant) and the plan of five cards (C24.1 to C24.5). |
| `plan-a1-integrity.md` | The plan of A-1 (D138 part 1, D140): one integrity check called by `check-manifest`, `verify-delivery` and `bump-round --verify`; who checks what today, the experiment that shows the gap, the design, four cards (C17.1 to C17.4) and the open decisions D-242a to D-242d. Written in round 242; a plan, no code. |
| `plan-a2-pins.md` | The plan of A-2 (D138 part 2, D144): what an edit of a pinned file costs, measured on a copy (one test red of 1632: the `pinned-*-move` tests freeze bytes), the two halves of A-2 read against the tree (the pin is already generated; fewer pinned modules rejected), two cards (C21.1, C21.2) and the open decisions D-270a to D-270d. Written in round 270; a plan, no code. |

| `integrity.md` | The shared rules about the project's own state (`integrity.mjs`): the exports, the four rules (`lf`, `pin`, `state`, `fingerprint`) and their `EINTEGRITY_*` codes, who calls them and with which reader; held to the code by `test/integrity-docs.test.mjs`. |

New docs (audits) go here as their cards land.
