## 3. Findings

- **F-1 (Windows, read not run). `smoke-test-tarball.mjs` does not quote its arguments on Windows; `pack-release.mjs` now does.** `const sh = WIN ? { shell: true } : {}` is passed to `spawnSync(cmd, args, …)` for `npm init`, `npm install … <tarball>` and every `.bin\*.cmd` call. With `shell: true` Node joins the arguments with spaces and quotes nothing, so a temp folder with a space (`C:\Users\Rodrigo Nascimento\AppData\Local\Temp\…`, any user name with a space) splits the tarball path, the `--root` paths and the `.cmd` command itself. On the GitHub runner the temp path is the 8.3 form without a space, which is why the round 290 fix can look right there. C24.6's own test for «a path with a space must survive» only runs `pack-release` on Linux; nothing covers the smoke script. Fix, one card: quote each argument and the command on Windows only (as `pack-release` does), or drive these calls with `execFileSync` on the `.cmd` through `cmd.exe /d /s /c` with one quoted string; a test that builds the command line for a path with a space (it can be tested as a pure function on any system). Not confirmed on Windows.
- **F-2 (design, small). A project made by `chicla init` has two versions that nothing keeps equal.** `init` writes `package.json` with the version of the `version.mjs` template (`0.0.1`, «one version, not two», comment in `init.mjs`), but the generated `CLAUDE.md` and status file tell the user to edit only `APP_VERSION` in `version.mjs` every round, and `verify-delivery` only requires that `package.json` exists. After the first round the delivered `package.json` says `0.0.1` forever. It is not wrong in a way anything measures; it is what D120 and C24.2 left between them. Options: say in the template that `package.json` carries no app version (then write it without one), or have `bump-round` refresh it (a kit source change). Decision for Rodrigo.
- **F-3 (docs overclaim). The README says the dump's digest «in `CLAUDE.md` is checked before anything from the zip runs» (`README.md` line 76, section «Emergency»); that is true of this repository, not of a project made by the package.** No template carries a `toolchain-digest:` line (grep of `packages/chicla-kit/templates/`: 0) and `bump-round` writes the pin only when the pinned files are in the project (`pinned(P)`), so for a package user there is nothing to compare. What really happens there is safe (`chicla recovery` runs the installed code and never code from the dump, `SECURITY.md` line 45 says so), but then the `RECOVER/` that C24.5 put in the dump is carried and checked by no documented step. Say it once in the README, or decide what `RECOVER/` is for in a package dump (a decision, not a bug).
- **F-4 (test quality). C24.6's test for the Windows fix reads the source with a regex** (`/shell:\s*WIN\b/` on the `execFileSync('npm'` line). Mutant E shows it works as a guard, but it checks spelling, not behaviour; nothing on Linux or macOS can show that Windows starts `npm`. That is a limit, not a defect: the real check is the next `tarball` run on Windows, which is Rodrigo's to read (it is `continue-on-error`, so a red Windows leg does not turn the run red).
- **F-5 (Windows, Node 24, low). `execFileSync('npm', [args], { shell: true })` is the deprecated form (DEP0190) on Node 24:** it prints a warning to stderr. CI uses Node 22, so nothing shows it yet; it matters only for a user on Windows with Node 24 who runs `pack-release`.
- **F-6 (runbook). `docs/release.md` still says «the CONTENT must be identical; not the bytes» for 0.2.1** (step 3). This audit got the same bytes as the CI tarball (see §1). The sentence is safe (a diff of the content is the stricter check to keep) but its reason is stale for this version; check `sha256` equality too, it is cheaper.
- **F-7 (record). ROADMAP names «D-283a to D-283c»** in the M24 heading, and the heading still says «proposed» although the cards are done (read the heading and D149; not checked row by row). Cosmetic.
- **F-8 (known, unchanged). Read in the tree: the `NEXT:` hint of `chicla recovery` prints `node scripts/make-delivery-zip.mjs`**, a path a package user does not have; it is in a pinned file, so it is documented (C24.4), not fixed.
- **F-9 (open from AUDIT-8 F-6). The two mutant lists still name nothing that M24 touched** (`init.mjs`, `zipkit-loader.mjs`, `toolchainPaths`, `build-chicla.mjs`, `pack-release.mjs`: 0 entries in `packages/chicla-kit/mutants/list.mjs`, 0 in the zip list; only `emergency-dump.mjs` is there, for older lines). The five hand mutants above are killed, so the tests are not empty; they are not in `npm run mutants:kit`, so the next round cannot repeat them with one command, and the 348-mutant zip list has not been run whole since 2026-10-28.
