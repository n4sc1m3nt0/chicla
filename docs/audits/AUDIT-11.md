## 3. Findings

- **F-1 (high, blocks the first push; process). The next push turns the CI red: the `main` of the repository is at round 304 (F-8) and tracks 188 files that the manifest does not list.** Measured: `git ls-remote` and a clone say `main` has `CHICLA_PROJECT_STATUS-309.md`, version 0.0.308 (that is round 304, F-8), one commit of 2026-11-02 10:59; rounds 305 to 317 were not on GitHub when it was cloned (2026-11-05), so the CI had not seen M27 or M28. The round 316 zip was pasted over the clone and `node scripts/check-manifest.mjs` (the CI runs it, `ci.yml` line 28) exited 1 with `EMANIFEST_TRACKED` and 188 files: 7 root `CHANGELOG-archive-rounds-*.md`, `CHICLA_PROJECT_STATUS-309.md`, 148 `docs/status-archive-*`, `dist` (6), `dist-0.2.0` (10), `dist2` (4), `dist3` (1), `distci` (3), `distkit` (3), 4 `notes*.md` and `t.mjs`. This is the guard of C27.2 doing what it was made for, but the cleanup never reached Rodrigo as one list (each round said only «`git rm -- CHICLA_PROJECT_STATUS-N.md`», which fits a repository pushed every round). Cleanup, validated in the clone and then run by Rodrigo on his disk (where the old status file was the -313 one and the root archives were already gone): the FIRST version of this command, with unquoted globs, failed in zsh with «no matches found» when a glob matched nothing and ran nothing (round 319); the version that works quotes the globs, adds `--ignore-unmatch`, and uses `--cached` for what stays on disk. From the root of the repository, after pasting the zip: `git rm -r -q --ignore-unmatch -- CHICLA_PROJECT_STATUS-309.md t.mjs 'CHANGELOG-archive-rounds-*.md' 'docs/status-archive-*'` and `git rm -r -q --cached --ignore-unmatch -- dist dist-0.2.0 dist2 dist3 distci distkit notes-chicla.md notes-kit.md notes-zip.md notes.md` (the old status file is the one the status file says). Running it a second time did what was needed: his first run left 25 tracked `.sha256` and `__MACOSX` files of `dist-0.2.0`, `dist2` and `dist3`, which `*.tgz.sha256` and `__MACOSX/` now ignore (C29.2). After it: `check-manifest` 513/513, `--verify` green, `test:fast` green (§2). The message of the guard lists only 15 names; it should group them and give this command (C29.1).
- **F-2 (medium; runbook). Following «Releasing chicla 0.3.0» recreates F-1.** Read: its step 3 points to the 0.2.1 step 3, which builds `dist2/`, `stage2/`, `ci/` and writes `notes-chicla.md` INSIDE the repository; `.gitignore` names `dist/ stage/ stage2/ ci/package/` and nothing else. A `git add -A` after the release would track `dist2/` and `notes-chicla.md` and the guard would fail again. (This is how `dist2`, `dist3`, `distci`, `distkit` and four `notes*.md` got into `main`.)
- **F-3 (medium; design). `ci-report` says «✓ no failing job» and exits 0 when a job was not judged.** Measured with a zip whose job log is above 64 MiB: stdout `✓ no failing job (1 job(s) read)`, the warning «this job was not judged» only on stderr, exit 0, `ok: true` in the `--json`. Someone reading the first line, or a script reading the exit code, takes an unjudged job for a green one.
- **F-4 (low; design). The cap of 5000 log entries is silent.** Measured: a zip with 6000 green jobs and a red one as entry 6001 gives `✓ no failing job (5000 job(s) read)`, exit 0. A real run has hundreds of entries, so this is unlikely, but it is the same kind of hole as F-3: a job that was not read is not reported.
- **F-5 (record, mine). The dates in the records of rounds 311 to 316 are wrong.** They say 2026-11-02 (taken from the name of the first zip); the file dates read from the sandbox clock were 2026-11-02 in round 310, 2026-11-04 in round 316 and it shows 2026-11-05 today. The exact day of each round in between cannot be read back from here, so those records are not edited; from round 317 the date is the sandbox clock's `date -I` (here 2026-11-05), also in the name of the zip.
- **F-6 (heads-up; not a defect). Three Dependabot pull requests are open** on the repository (read with `git ls-remote`, as `refs/pull/*`): v7 of `actions/checkout`, `actions/setup-node` and `actions/upload-artifact`. The tree pins v6.0.0 for the three (D157, confirmed). The tests accept «v6 or later», so merging them later is possible; merging one of them now changes the pin of a workflow that has not been seen green. Rodrigo's call.
- **F-7 (known; not new). 62 of the 189 kit mutants were not judged in round 315** (counted from the runner's list: 127 judged, all RED) (they point at files that round did not touch). Not a defect, a debt: one detached run of about 100 minutes on this machine (each mutant re-runs its own baseline).
- **F-8 (record, mine). The audit, the status file, the CHANGELOG, the ROADMAP and the index of `docs/` gave a wrong round, 308, for the repository `main`; it is at round 304.** Read: the CHANGELOG headings pair a round with the version (`## Round 304 — … (v0.0.308)`, `## Round 308 — … (v0.0.312)`), the status file number is the round plus five (`CHICLA_PROJECT_STATUS-309.md` is round 304), and the `main` has `package.json` 0.0.308 and `version.mjs` with `seq=309`.
