## 3. Findings

- **F-1 (record, mine). Round 310 wrote «the `pack` job»; the job in `ci.yml` is `pack-chicla`** (`grep -n "^  [a-z-]*:$" .github/workflows/ci.yml`: `test`, `windows`, `bench`, `pack-chicla`, `tarball`). The line 93 that changed is in `pack-chicla`. Fixed in this round in the three places of round 310 (CHANGELOG entry, Snapshot, «Last updated»); the words of round 309 and the ROADMAP card text keep the old name as history.
- **F-2 (design, medium). `ci-report` calls a `continue-on-error` job failed, so its exit is 1 for a run that GitHub shows green.** Measured with a synthetic zip of three jobs (`test` green, `test` red, `tarball (windows)` with only an `##[error]` line): `2 of 3 job(s) failed`, exit 1. `ci.yml` marks the Windows leg of `tarball` `continue-on-error` («REPORTED, not promised», D114), and a failed step of such a job writes `##[error]` in its log, which is D154's rule for «failed». The log does not say that the job is allowed to fail. Rodrigo will see exit 1 on every Windows red.
- **F-3 (test gap, small). `ci-report` fails a job on a `not ok` line, but no test needs that alone.** Mutant C2 (drop `failing.length > 0`) survives because every test log also has `# fail N` above 0. A log that stops before the summary (a cancelled or killed job) has `not ok` and no `# fail`; the `##[error]` rule usually catches it, but that is a second rule doing the work of the first.
- **F-4 (stray file). `t.mjs` is in the root and in the manifest.** Read: 3 lines, it imports `/tmp/w/packages/chicla-kit/src/panel.mjs` (a sandbox path of round 307) and prints a panel; grep finds no reference to it in the tree. A deletion needs `--allow-removed t.mjs` and Rodrigo's word (item 14).
- **F-5 (stale words, cosmetic).** grep: four test files (`plan-a2-docs`, `init-package-json-docs`, `dump-limit-docs`, `plan-a1-docs`) still say in comments, and `docs-accuracy.test.mjs` line 189 in a test title, `docs/status-archive-*` for what is now `docs/archive/status/`.
- **F-6 (release, medium). The tree's `chicla` is 0.2.1 and is not the published 0.2.1.** Measured: this tree's tarball is `chicla-0.2.1.tgz`, sha256 `ef00035c7ca6…`; the published one is `554cbbc7…abf6` (G-C17). Since then the tree gained `chicla init --name`, `chicla rename-status` and `chicla ci-report` (M26 and M27); `packages/chicla/README.md` names none of them (grep: 0). `npm publish` of 0.2.1 again would be refused, and a user of `npx chicla@0.2.1` has fewer commands than the repository README describes. ROADMAP and `docs/release.md` have no card or gate for the next version (grep for 0.2.2 and 0.3.0: none).
- **F-7 (test coverage, small). `scripts/smoke-test-tarball.mjs` drives nine steps from the installed package and none of them is `ci-report`, `rename-status` or `init --name`** (grep: 0 references). They work from the package (measured by hand for `ci-report`, §2), but nothing in the CI would show it if a later build left a file out.
