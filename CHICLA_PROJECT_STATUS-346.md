Start it DETACHED, with a log that ends in an `EXIT` line: `setsid nohup bash -c 'npm test > /tmp/test.log 2>&1; echo "EXIT $?" >> /tmp/test.log' > /dev/null 2>&1 < /dev/null &`, then wait with ONE bounded call at a time: `timeout 270 bash -c "until grep -q '^EXIT' /tmp/test.log; do sleep 5; done"; tail -n 8 /tmp/test.log` (270 s stays under the shortest call limit seen; a 6 min suite is 2 waits instead of ~20 polls, because every call re-sends the whole context). (b) While coding run only the file at hand, with `timeout 120`. To check a round before closing, `npm run test:fast`: every file `npm test` runs except the 7 slow integration files named in `scripts/run-tests.mjs`; it took 213 s for 1472 tests, measured on 2026-10-26 (round 248) in this sandbox, which has 1 core (measured in round 240: 160 s for 1406 tests; the suite grows, so measure again before you trust either) (`nproc` = 1, so `node --test` cannot overlap files); wait for it as in (a), two waits. `npm run test:slow` is the other part (those 7 files, about 220 s). Fast plus slow are exactly the files of `npm test` (`test/test-sets.test.mjs`), and the CI keeps running the full `npm test`; so does the closing run: the whole `npm test` once per round, after `bump-round`. (c) Mutants: only the round's own, `--only <id> --timeout 60`, one at a time, detached as in (a); the full list only when Rodrigo asks, else report it as NOT run (item 18). The kit has its own list: a round that touches a kit source (`packages/chicla-kit/src/`) runs the entries of that file the same way (`npm run mutants:kit -- --only <id> --timeout 60`, detached as in (a); `--pkg .` is built in, it copies the whole tree) or the whole `npm run mutants:kit` (about half an hour on 2 cores, measured in round 265; the `K-VER-` entries, which build zips, are three quarters of it; always detached) and adds an entry for a guarantee it adds; `docs/README.md` lists `packages/chicla-kit/mutants/list.mjs`. (d) If a wait ends with exit 124 (no `EXIT` yet), compare `wc -c` of the log with its size before that wait: a log that grew is not hung, wait again; a log that did not grow in a whole wait is hung: kill it (`pkill -f 'node --test'`, `pkill -f mutants.mjs`), read `tail -n 25`, run the one file that was last active once; a second hang means STOP, report it and deliver what builds (item 15). (e) A hang is a finding: name it, never raise a timeout, skip a test or drop a mutant without Rodrigo's word.
